# 0061: Structured JSON logs to stdout without secrets

- Status: Proposed
- Date: 2026-09-14
- Scope: Required (v1)
- Source: [Technical architecture › Observability policy, Stack log viewer, Backend](../technical-architecture.md#observability-policy)
- Related: [0005](0005-production-log-path.md), [0025](0025-authentication-rate-limiting.md), [0027](0027-activity-audit-events.md), [0064](0064-observability-stack.md), [0066](0066-deferred-tracing.md)

## Context

Logs are collected from container output (journald → Alloy → Loki in production, Dozzle for live viewing) and must be searchable without leaking credentials.

## Decision

Application containers write structured JSON logs to stdout/stderr. Each entry includes timestamp, level, service, request ID, user ID where appropriate, route, status, duration, and error details. Never log passwords, tokens, or sensitive request bodies. Security events (such as failed logins) are logged in structured form without passwords or tokens.

## Consequences

- Logs can be queried by field in Loki.
- Every log call site must respect the redaction rules.
